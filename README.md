A browser-first product laboratory and tooling platform for transforming existing software capabilities into focused standalone products. This repository contains the Lovable-generated web application foundation that powers codebase intake, interactive system visualizations, and the product laboratory UI.

Quick goals:
- Provide a polished, extensible foundation for interactive codebase analysis and system visualization.
- Keep the product immediately usable without mandatory accounts or monetization.
- Build components that can be reused by many IRS products (graph visualization, code intake, product catalog).

Features
- Browser-first UI with interactive system graph and product laboratory concepts.
- Codebase intake flows: GitHub/GitLab URL, ZIP upload, local folder (architectural placeholders).
- Reusable graph model and renderer (prepared for GPU/canvas-based rendering).
- File-based routes (TanStack Start file routing).
- Clean error pages and server-side error normalization.
- Prepared architecture for later payment/verification (disabled by default).

Stack
- Language: TypeScript (primary)
- Framework / runtime: TanStack React Start + Vite, React 19
- Router: @tanstack/react-router and @tanstack/react-start
- UI primitives: Radix UI, Tailwind CSS, Lucide icons
- Notable libraries: @tanstack/react-query, zod, react-hook-form, recharts

How it fits together
- The client app is rendered with TanStack Start routes (file-based). `src/routes/__root.tsx` defines the app shell and global providers (QueryClient). The server entry (imported at runtime) is wired through `src/server.ts` which normalizes errors and serves SSR responses. `src/start.ts` sets up middleware (error handling, CSRF protection for server functions). Routes live in `src/routes/` and `routeTree.gen.ts` is generated by the tooling.

How to run

Prerequisites
- Node >= 18 (or use nvm to install)
- npm (or use bun if preferred; the repo includes a bun.lock)

Quick start (development)
```bash
git clone https://github.com/casey-arch0/irs-intelligence-research-systems.git
cd irs-intelligence-research-systems
npm install
npm run dev
# open http://localhost:5173 (or the port Vite prints)
```

Build & preview
```bash
npm run build
npm run preview
```

Important files to inspect
- src/routes/__root.tsx — application root, error + notFound pages, <Outlet/> to render children
- src/start.ts — request middleware (error handling, CSRF filter)
- src/server.ts — SSR/server fetch handler and error normalization
- src/routeTree.gen.ts — generated routing tree; do not edit directly
- src/styles.css — global styles and Tailwind base

Development notes & conventions
- File-based routing: every `.tsx` file inside `src/routes/` defines a route. See `src/routes/README.md` for conventions (dynamic segments, optional segments, layout routes).
- Error handling: Errors from server functions are filtered by the CSRF middleware in `src/start.ts`. SSR errors are normalized in `src/server.ts` to render the user-facing error page instead of exposing raw JSON.
- Generated code: `routeTree.gen.ts` is generated; do not edit.
- Keep the code modular: presentation, graph rendering, and codebase analysis should remain separated.
- Monetization & accounts: intentionally disabled during current development. Do NOT add active monetization, registration, or payment flows in the main branch.

Lovable / repository sync note (IMPORTANT)
> This project is connected to Lovable. Avoid rewriting published git history — do not force-push, rebase/amend/squash commits that are already pushed. Commits pushed to the connected branch sync back to Lovable and show up in the editor; keep the branch in a working state.

Design & product guidance (summary)
- Interactive systems graph is a first-class feature: prioritize performance with progressive loading, clustering, and GPU/canvas rendering when needed.
- Graph modes: dependency, causality, architecture, activity, timeline, impact.
- Codebase intake: support repository URL, ZIP upload, local folder selection; prefer local processing where possible.
- Product laboratory: data-driven product cards, statuses (Research, Building, Live).

Testing & CI
- ESLint & Prettier are configured; use `npm run lint` and `npm run format`.
- There is no CI pipeline included in the repository by default; add GitHub Actions or other CI carefully and avoid breaking the Lovable sync.
